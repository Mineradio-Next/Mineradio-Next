# 歌单整理与同步设计

## 目标

把现有音乐库从“能导入、能播放”推进到可长期维护的资料整理区。功能沿用 Mineradio 原版的轻玻璃、紧凑列表和短缓动，不复制衍生项目的二级资料库页面，也不向播放器底栏或视觉控制台追加入口。

## 方案选择

1. **在现有音乐库内增强（采用）**：歌单管理留在“我的歌单”，重复项和失效文件进入新的“曲库健康”页。职责清楚，复用现有持久化与播放路径，升级成本最低。
2. 新建独立“歌单中心”：层级更完整，但会制造第二套音乐库导航和重复的列表状态。
3. 只增加几个操作按钮：改动小，但没有同步状态、健康检查和后续扩展位置，容易再次把详情头部塞满。

## 信息架构

音乐库保留原有“本地音乐 / 我的歌单 / 导入与交换”，新增“曲库健康”。

- “我的歌单”左侧仍是歌单目录，右侧改为固定的歌单资料头和曲目列表。
- 歌单资料头包含封面、可编辑名称、歌曲数量、来源、最近更新时间和主操作。
- 自建及导入歌单可更换封面；只有来自平台分享链接的歌单显示“刷新同步”。
- 曲目列表提供稳定的拖拽手柄和上移/下移按钮，不依赖一条难命中的拖拽区域。
- “曲库健康”展示本地音乐重复组、失效索引和检查时间。危险操作使用二次确认，并明确只移除索引。

## 数据契约

本地歌单目录继续由 `desktop/local-playlist-catalog.js` 持久化。歌单新增并保留以下可选字段：

- `importedProvider`：平台来源标识。
- `sourceInput`：用户原始分享链接或歌单 ID，用于再次同步。
- `fingerprint`：最近一次远端快照指纹。
- `syncedAt`：最近成功同步时间。
- `customCover`：用户自定义封面；与远端封面分开，刷新时不覆盖。

手动加入平台导入歌单的歌曲记录 `userAdded: true`。刷新同步时用来源和歌曲身份替换远端部分，再把仍有效的本地手动歌曲合并到尾部并去重。旧数据没有标记时采用保守策略：远端缺少的旧歌曲仍保留，避免首次升级发生静默丢歌。

歌曲顺序直接持久化在歌单 `songs` 数组中。拖拽只在当前完整歌单、非搜索结果状态启用。

## 交互与视觉

- 封面操作放在封面本身的轻悬浮层，常态不占标题空间。
- 同步按钮只在可同步歌单出现；同步中保持原布局并显示轻量忙碌状态。
- 拖拽行使用位移和细边框反馈，不改变行高；键盘和上/下移按钮提供等价路径。
- 健康页使用全宽摘要带和紧凑问题分组，不使用卡片套卡片。
- 小窗口下歌单目录收为横向选择带，详情保持单列，文本不能挤成竖排。

## 错误与安全边界

- 同步失败时保留完整旧歌单，不写入半成品。
- 自定义封面读取或保存失败时保留旧封面。
- 排序持久化失败时恢复操作前顺序并提示。
- 健康清理只调用现有本地曲库索引删除接口，绝不删除音频文件。
- 同一歌单只允许一个同步或排序写入在途，避免快速操作覆盖新状态。

## 测试

- 目录规范化保留同步和自定义封面字段，拒绝无效或超长值。
- 平台刷新替换远端歌曲、保留手动歌曲、去重并在失败时保持旧快照。
- 排序覆盖拖拽顺序、上移/下移边界和持久化失败回滚。
- 健康检查稳定分组重复项、识别失效索引，并验证清理不包含任何磁盘删除路径。
- UI 集成测试验证独立健康页、同步入口、封面入口、拖拽手柄、响应式规则以及无衍生品牌命名。
