# 本地曲库与歌单工作流设计

## 目标

把已经存在但分散在上传按钮、左侧歌单栏和播放器动作中的本地音乐能力，整理成一个可长期维护的独立工作区。用户在一个地方完成文件导入、文件夹浏览、批量选择、歌单整理和歌单交换；当前播放队列仍保持轻量，不承担资料管理职责。

## 信息架构

新增独立的“音乐库”工作区，并保留首页“音乐库”卡片作为主入口。顶栏导入按钮旁增加一个图标入口，方便播放过程中随时返回音乐库。

工作区包含三个一级视图：

1. **本地音乐**：歌曲搜索、全部/文件夹切换、批量选择、播放全部、加入队列、从曲库移除。
2. **我的歌单**：创建、重命名、删除、播放、加入队列、逐曲移除和导出。
3. **导入与交换**：导入歌曲、导入文件夹、导入歌单文件、导入平台分享链接，并明确展示支持范围。

左侧歌单面板继续承担快速浏览、当前队列和歌单快捷播放。视觉工作台只保留视觉参数；应用设置只保留路径或行为类配置，不放曲库内容管理。

## 数据与兼容

- 本地音频索引继续由 Electron 主进程的 `LocalMusicLibrary` 管理，保持原文件不复制、不修改。
- 删除操作只从 Mineradio 曲库索引移除，不删除磁盘上的音乐文件。
- 本地歌单继续兼容已有浏览器存储，并增加 Electron 用户目录下的原子快照，避免大歌单受 `localStorage` 容量限制。
- 新导出的原生歌单扩展名为 `.mrpl`，载荷类型为 `mineradio_playlist_v1`。
- 导入端静默兼容旧的 gzip 歌单格式及 `.lxmc` 文件，但界面、按钮、说明和默认文件名不出现衍生项目名称。
- 同一歌单内按来源、歌曲 ID、标题和歌手组合去重；重复导入同一平台歌单时更新原歌单，不生成副本。

## 大列表策略

- 本地曲库和歌单详情都采用分批渲染；过滤或切换文件夹时重置窗口，不一次向 DOM 写入全部歌曲。
- 已有左侧歌单详情的增量请求和虚拟列表保持不变。
- 工作区只渲染当前筛选结果的首批行，滚动接近底部时增加可见数量。
- 搜索结果“下一首播放”沿用统一的 `queueSongNext`，避免各页面分别实现队列插入规则。

## 交互与视觉

- 工作区使用原版的深色玻璃、细描边、短距离淡入与列表错峰进入，不引入新的色彩体系。
- 一级视图使用分段标签；批量选择使用复选框；播放、加入队列、导入、导出等明确命令使用图标加文字。
- 内容区是连续的列表和工具栏，不把页面拆成层层嵌套的卡片。
- 关闭工作区后回到原播放场景，播放不中断；`Esc` 仅关闭当前工作区或子对话框。
- 尊重 `prefers-reduced-motion`，关闭错峰和位移动画。

## 错误处理

- 导入失败显示成功数、跳过数和失败原因，不因单个文件失败丢弃已成功部分。
- 曲库索引和歌单快照均使用临时文件加原子替换；写入失败保留上次有效版本。
- 批量移除必须二次确认，并明确说明不会删除磁盘文件。
- 不支持或损坏的歌单文件只影响该文件，其余文件继续导入。

## 验证

- 单元测试覆盖本地曲库批量移除、原子回滚、歌单迁移、原生格式和旧格式兼容、去重及大列表分批渲染。
- 前端静态测试覆盖独立入口、三个一级视图、下一首统一队列函数和界面禁用衍生命名。
- 运行全量 Node 测试和 Electron quick-check。
- 生成 Windows 安装包并启动 `win-unpacked` 验收版，确保不打开 DevTools。
