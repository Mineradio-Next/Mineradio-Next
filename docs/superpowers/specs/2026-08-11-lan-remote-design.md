# Mineradio 随身控制设计

## 目标

在 Windows 客户端中增加一个需要用户主动开启的局域网遥控器。手机与电脑连接同一 Wi-Fi 后，扫描二维码即可控制当前 Mineradio 播放，不需要安装手机应用，也不改变现有音乐服务的本机监听边界。

功能名称统一为“随身控制”，代码、界面和路由中不出现 LX 品牌。

## 范围

第一版包含：

- 桌面端开启、停用和重新生成遥控会话。
- 二维码、局域网地址和复制连接入口。
- 手机端当前歌曲、歌手、专辑、播放进度、播放状态和队列摘要。
- 播放、暂停、上一首、下一首和音量控制。
- 遥控页连接状态、命令反馈和断线恢复。

第一版不包含：

- 手机端搜索、登录、收藏、歌单编辑和来源配置。
- 远程访问、云中转、NAT 穿透或公网控制。
- 将主 `server.js` 改为局域网监听。
- WebSocket 依赖；状态同步使用短轮询，降低维护成本。

## 入口与视觉

入口位于现有视觉控制台标题栏，与“热键”同级，按钮名为“设备”。点击后打开“随身控制”面板，不向首页增加新卡片。

桌面面板沿用 Mineradio 的黑色半透明玻璃、细边线、低饱和高亮和紧凑按钮语言。开启前显示本机、Wi-Fi、手机三段连接关系；开启后以二维码为视觉中心，旁边显示会话状态、局域网地址、连接设备数和剩余时间。

手机端是实际控制器而非说明页。首屏由当前曲目信息、进度轨、三枚传输控制、音量轨和接下来播放组成。视觉使用深色背景、封面色氛围、细网格和原版克制的高亮，不复制 LX 的卡片布局。

## 架构

### 独立遥控服务

Electron 主进程创建独立 HTTP 服务，开启时监听 `0.0.0.0` 的随机可用端口，停用或应用退出时关闭。现有 Mineradio 主服务继续只监听 `127.0.0.1`。

遥控服务只提供：

- `/`、`/remote.css`、`/remote.js` 三个固定静态资源。
- `GET /api/state`，返回清洗后的播放状态。
- `GET /api/artwork`，以受控代理形式返回当前封面，不在 JSON 中暴露原始地址。
- `POST /api/command`，接收白名单控制命令。

### Electron 桥接

预加载层只暴露五个窄接口：开启、停用、读取状态、上报播放状态、订阅遥控命令。主进程校验 IPC 发送者必须是 Mineradio 主窗口。

渲染进程复用现有 `togglePlay`、`nextTrack`、`prevTrack` 和 `setVolume`，不建立第二套播放器状态。状态上报只包含显示所需字段，封面源只在主进程内部使用。

### 状态同步

渲染进程每 700 毫秒生成一次轻量播放快照；内容未变化时主进程只更新时间字段。手机端每 800 毫秒轮询一次状态，并在页面不可见时降低频率。

## 安全边界

- 每次开启生成 256 位随机令牌，令牌放在二维码 URL 的 fragment 中，不随首个页面请求发送。
- API 只接受 `Authorization: Bearer <token>`。
- 会话八小时后过期；停用、重新开启或退出应用会立即轮换令牌。
- 命令仅允许 `play`、`pause`、`previous`、`next` 和 `volume`。
- 请求体限制为 4 KB；音量限制在 0 到 1；单客户端命令频率受限。
- 公共状态不包含 Cookie、账号标识、音频 URL、封面 URL、本地文件路径或来源脚本信息。
- 静态资源设置 `no-store`、`nosniff`、禁止 iframe 和严格 CSP。

## 错误处理

- 没有可用局域网地址时不启动，并在桌面面板说明需要连接 Wi-Fi 或有线局域网。
- 令牌无效或过期返回 401，手机端显示连接已结束。
- 播放器未准备好时命令仍会被安全接收，由渲染进程返回当前空状态，手机端保持可恢复。
- 遥控服务异常关闭时桌面面板恢复为未启用状态，不影响本机播放。

## 验收

- 主服务仍只监听 `127.0.0.1`。
- 未开启随身控制时没有额外局域网监听端口。
- 开启后二维码和复制地址可访问手机控制页。
- 无令牌、错误令牌和过期令牌无法读取状态或发送命令。
- 非白名单命令、超大请求体和越界音量被拒绝。
- 手机端控制调用现有播放器函数，桌面播放状态正确变化。
- 状态 JSON 不含 URL、Cookie 和本地路径。
- 桌面 1440×900 与手机 390×844 下无重叠、溢出或不可点击控件。
