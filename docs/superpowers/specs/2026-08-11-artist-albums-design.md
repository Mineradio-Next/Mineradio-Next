# 歌手专辑作品设计

## 目标

在现有“歌手详情”中补上真正的专辑浏览入口，让用户从当前歌曲进入歌手页后，可以继续查看该歌手的专辑，并复用 Mineradio 已有的专辑播放、收藏和无缝衔接能力。

本批只增加“专辑作品”，不改动首页、播放器主布局、菜单结构和现有热门歌曲列表。

## 产品边界

- 面向网易云和 QQ 音乐歌曲展示真实歌手专辑。
- 不使用 LX 名称、菜单或视觉文案。
- 不把热门歌曲按专辑名临时拼成伪专辑列表。
- 不增加新的专辑播放实现；点击专辑后进入现有“专辑详情”。
- 酷狗、汽水、Spotify 和附加来源在缺少稳定歌手专辑接口时保持现状。
- 专辑接口失败不影响歌手资料和热门歌曲。

## 交互

歌手详情加载后，在歌手资料与热门歌曲之间显示“专辑作品”。专辑采用横向可滚动条带，每张作品包含方形封面、专辑名、发行年份和曲目数；鼠标悬停轻微上浮，键盘 Enter/Space 均可打开。

点击专辑时构造一条只包含专辑身份的来源歌曲，并调用现有 `openTrackDetailModal('album', song)`。随后由现有专辑详情负责：

- 拉取完整曲目；
- 播放整张或指定曲目；
- 设置无缝播放上下文；
- 收藏专辑；
- 收藏单曲或加入下一首。

专辑加载中使用骨架占位。结果为空时不显示空卡片区，只保留热门歌曲。请求失败时显示一行克制的错误状态，不阻断热门歌曲。

## 数据契约

`/api/artist/detail` 与 `/api/qq/artist/detail` 返回统一的 `albums` 数组：

```json
{
  "provider": "netease",
  "artist": { "id": "6452", "name": "周杰伦" },
  "albums": [
    {
      "provider": "netease",
      "id": "123",
      "name": "专辑名",
      "artist": "歌手名",
      "cover": "https://...",
      "releaseDate": "2024-01-01",
      "trackCount": 12
    }
  ],
  "songs": []
}
```

QQ 专辑另外保留 `mid` 与 `albumMid`；网易云保留数值 `id`。前端只读取统一字段，不解析上游原始响应。

## 后端

- 网易云：使用 `artist_album`，与歌手资料、热门歌曲并行容错加载。
- QQ 音乐：调用 `music.web_singer_info_svr.get_singer_album`，映射 `album_mid`、`album_name`、`pub_time` 和 `latest_song.song_count`。
- 每次最多返回 12 张专辑，前端首屏展示不超过 8 张，避免歌手详情过长。
- 上游专辑请求失败时返回 `albums: []` 和可选 `albumError`，HTTP 状态仍由歌手详情主请求决定。

## 视觉

沿用现有详情弹窗的暗色玻璃层、细边框和小字号。专辑不是独立大卡片墙，而是紧凑横向作品条带：封面承担主要识别，文字只占两行，降低方盒堆叠感。卡片圆角不超过 10px，动效只使用 `transform`、边框和背景变化，并尊重 reduced-motion。

小窗口下仍保持横向滚动，不压缩成难以辨认的小封面，也不扩大详情弹窗宽度。

## 错误与竞态

- 继续复用 `trackDetailSeq`，关闭或切换详情后忽略迟到响应。
- 歌手名称不匹配时，专辑和热门歌曲都不渲染。
- 无封面时显示与当前歌手头像同体系的占位块。
- 点击无有效专辑 ID/MID 的条目不发请求，并给出提示。

## 验证

- 单元测试覆盖网易云与 QQ 专辑映射、路由接线和前端专辑身份构造。
- 全量 `node --test` 与 `quick-check.bat` 通过。
- 隐藏 Electron QA 检查 1440x900、1280x720：无横向页面溢出、无重叠，专辑点击能进入专辑详情。
- Windows 目录包构建成功，最终只重启普通客户端供用户验收。
